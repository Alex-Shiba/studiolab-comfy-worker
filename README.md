# StudioLab: отдельный видеоворкер Vast

Endpoint `studiolab-comfy` принимает параметры ролика, выполняет один фиксированный граф MiniMax H3 Turbo8 и возвращает MP4. SAM остаётся отдельным endpoint. Клиент не передаёт графы, имена узлов, пути или URL картинок. Этот каталог — самостоятельная единица развёртывания: `worker.py` и `requirements.txt` должны лежать в корне опубликованного репозитория.

## Шаблон первого испытания

| Настройка | Значение |
| --- | --- |
| Образ | `vastai/base-image:cuda-13.0.2-cudnn-devel-ubuntu24.04-py310-2026-03-18` |
| Запуск | Штатный supervisor / `start_server.sh`, без provisioning script |
| `PYWORKER_REPO`, `PYWORKER_REF` | Репозиторий этого каталога и полный неизменяемый commit; задаёт conductor |
| `SDK_VERSION` | `1.8.3`, без `SDK_BRANCH` |
| Публичный порт | Только `3000:3000`; `WORKER_PORT=3000`, `USE_SSL=true`, без `UNSECURED` |
| GPU | NVIDIA; VRAM ≥ 24 GB; compute capability ≥ 8.6; `cuda_max_good` ≥ 13.0 |
| Диск и сеть | Диск ≥ 120 GB; быстрое скачивание; запас места желателен |
| RAM | Рекомендуется ≥ 64 GB, предпочтительно 96 GB для offload |
| Endpoint | `studiolab-comfy`, `max_workers=1`, без тёплого/холодного резерва |
| Простой | `COMFY_SELF_DESTRUCT_IDLE_S=540`; `0` отключает и idle-, и fatal-удаление |
| Маркеры SDK | `COMFY_LOG_FILE=/var/log/portal/comfy-worker.log` |
| Диагностика | `COMFY_DIAGNOSTIC_LOG=/var/log/portal/comfyui.log` |

**720p на 24 GB не проверено.** Фильтр первого испытания не гарантирует вместимость. Conductor проверяет единицы `gpu_ram`, синтаксис фильтра, драйвер и пики памяти/диска. ComfyUI слушает только `127.0.0.1:8188`, модельный API — `127.0.0.1:18001`. Внутренний webhook-порт SDK 3001 нельзя публиковать.

Очередь живёт дольше HTTP-запроса start. Студия регулярно опрашивает state через route во время генерации. Начальное значение endpoint `inactivity_timeout` — 1200 секунд; его нужно согласовать с реальным интервалом опроса и холодным стартом. Удаление по настоящему простою выполняется через 540 секунд. Все четыре session handler SDK (`create`, `get`, `end`, `health`) заменены одним ответом 404 `{"error":"unknown"}` без чтения тела, включая handler внутреннего webhook-приложения. `max_sessions` не используется как защита.

`CONTAINER_ID` и `CONTAINER_API_KEY` поступают от Vast. Ключ удаления остаётся только в родителе. Окружение ComfyUI, установщиков и модельного сервера очищается от ключей, токенов, паролей и секретов; MASTER_TOKEN нужен только прокси. `COMFY_JOB_ROOT`, `COMFY_RETIRE_FILE` и `COMFY_BENCHMARK_ID` создаются родителем, их не задают в шаблоне.

По данным conductor этот стек уже работал локально. Здесь повторного GPU-испытания не было. Исходник H3 не требует `--enable-triton-backend`, поэтому флаг отсутствует. Загрузка проверяет точную версию Python и torch, CUDA 13.0, наличие GPU и обязательно `comfy_kitchen.registry.is_available('cuda')`. Недоступный backend вызывает `COMFY_FATAL install` до скачивания весов.

## Загрузка, ошибки и журналы

1. Родитель очищает файл маркеров, запускает PyWorker **до установки и скачивания**, включает watchdog на **25 минут**. Прокси следит за маркерами; готовность объявляется только после `COMFY_READY`.
2. `COMFY_STAGE install`: проверка commit/tag ComfyUI, создание окружения через `uv venv --managed-python --python 3.13.9`, установка зависимостей и проверка CUDA backend. `COMFY_STAGE download`: загрузка моделей по неизменяемой revision. Проверяются размер и SHA-256; сегменты докачиваются, установка файла атомарна. Временные ошибки, HTTP 429/5xx и неверный Range повторяются до общего watchdog с задержками 1, 2, 4, 8, 16, 30 секунд, далее по 30 секунд. Прогресс сегмента сбрасывает задержку; байты неверного Range удаляются. Несовпадение контрольной суммы завершает загрузку сразу.
3. `COMFY_STAGE comfy`: запуск ComfyUI с native nodes, loopback, offline, без custom nodes, превью и метаданных. `/object_info` должен содержать все нужные узлы. **Кеш моделей сохранён между роликами**; `--cache-none` отсутствует.
4. `COMFY_STAGE server`: запуск модельного API, проверка `/health`, затем `COMFY_READY`. Единственный SDK benchmark читает временную failed-запись через state; он не рендерит и не проверяет производительность GPU. Первая настоящая генерация загружает веса.
5. Ошибка установки/скачивания/запуска, выход дочернего процесса или watchdog приводит к `COMFY_FATAL <stage> <ExceptionClass>`. Генерация останавливается; если прокси исправен, он остаётся жив минимум около **15 секунд** для отправки ошибки SDK, затем родитель вызывает `self_destruct`. SDK сначала сопоставляет маркеры конкретных этапов, затем общий: в сообщение Vast попадает, например, `COMFY_FATAL download`. Класс исключения остаётся в журнале. Выход прокси помечается этапом `proxy`, в том числе до READY.
6. DELETE повторяется с задержками 1, 2, 4, 8, 16, 32, 60 секунд, далее каждые 60 секунд, пока процесс жив. Любой неуспешный статус, включая 401/403/429, повторяется. 2xx или 404 завершает удаление. После успеха второго DELETE нет. Отсутствующие credentials дают фиксированный skip-маркер; `COMFY_SELF_DESTRUCT_IDLE_S=0` — явное отключение.

Вывод ComfyUI, модельного сервера и прокси одновременно попадает в stdout контейнера (Vast instance logs) и `/var/log/portal/comfyui.log`. Ротация: текущий файл и три резервных по 5 MiB, суммарно около **20 MiB**. Промпты владельца могут встречаться в диагностике. Значения credential-переменных длиной от восьми символов редактируются до обоих выходов, включая границы блоков; `0`, `1`, `true`, `false` не редактируются. Окружение не печатается. SDK DEBUG отключён. Диагностика не очищается вместе с каталогом задания; удаление экземпляра уничтожит и журналы. Маркеры содержат этап и класс исключения, без текста исключения. При отказе записи маркера он выводится в stdout, а удаление продолжается.

Модельный сервер отслеживает запросы/задания и при простое передаёт родителю локальный сигнал-файл. Пока удаление выполняется, новые задания не принимаются. Queued/running-задания и незавершённые запросы не считаются простоем; health-пробы не продлевают жизнь. SIGTERM/SIGINT останавливают детей и очищают временный каталог.

Холодный старт должен уложиться в **15 минут ожидания route** у студии; это пока не измерено. Watchdog 25 минут — предел удаления зависшей загрузки, а не обещание студии ждать дольше. Сегменты и сборка временно занимают две копии одного файла. Удаление экземпляра уничтожает диск.

## Транспорт и контракт ревизии 2

Перед каждым вызовом студия запрашивает `POST https://run.vast.ai/route/` для `studiolab-comfy`: cost 100 для start, 1 для state/file. На адрес воркера отправляется `{"auth_data": <route answer>, "payload": <body>}` по HTTPS с закреплённым Vast root CA и проверкой SAN.

**Route answer (`auth_data`) — bearer-секрет на всё время жизни воркера. SDK не делает подпись одноразовой.** Студия не должна логировать, сохранять или показывать его. Свежий route для каждого вызова сохраняется как правило транспорта, а не защита от replay. Внешний contract.md всё ещё содержит противоречащую этому фразу; поправка за conductor.

### POST /clip/start

Обязательные поля: `request` (32 строчных hex), `mode` (`text`/`frames`), `prompt` (1–4000 символов), `seconds` (целое **5–10**), `size` (`480p`/`720p`), `aspect` (`16:9`/`9:16`/`1:1`), `seed` (целое 0–2147483647), `audio` (boolean).

Для `frames` нужен `first`, необязательный `last` допустим только вместе с ним. Кадры — base64 JPEG/PNG до 12 MiB каждый, до 16 777 216 пикселей и 8192 по стороне, без анимации. Проверяются структура и пиксели. Для обоих кадров выполняется **EXIF-transpose, центральный cover-crop к фактическому canvas и сохранение PNG** в каталоге задания. Кадры не растягиваются. У `text` кадров нет. Неизвестные/повторные ключи, NaN, числовые строки и boolean вместо integer отвергаются. Тело ограничено двумя изображениями и 64 KiB; SDK envelope получает ещё 64 KiB.

- 200: `{"id":"<32 lowercase hex>","state":"queued"}` для нового задания.
- Повтор с тем же request и всеми теми же полями, включая байты кадров: тот же id и **текущее** состояние; второго задания нет.
- Тот же request с другими полями: 409 `{"error":"conflict"}`.
- 400: `{"error":"invalid","detail":"<short English>"}`.
- 429 `{"error":"busy"}`: заняты одно выполняемое и два ожидающих места либо backend недоступен/удаляется. Уже известный request проверяется раньше: 429 не стирает и не скрывает задание.

### POST /clip/state и /clip/file

Оба принимают только `{"id":"<32 lowercase hex>"}`. State возвращает состояние queued/running/done/failed, progress 0..1, fps=24, реальные width/height/frames; после завершения — exec_s, при ошибке — короткий error. Неизвестный id: 404 `{"error":"unknown"}`. Неверный формат id: 400.

File возвращает весь MP4 с `Content-Type: video/mp4` и точным `Content-Length`; Range не меняет ответ. До готовности — 409 `{"error":"not_ready"}`, после истечения срока — 404. Файл можно получить повторно. Конкурирующая загрузка получает 404; незавершённая передача освобождает файл для следующей попытки.

Задание, fingerprint request и MP4 хранятся **1800 секунд после done**, включая скачанный файл; failed-записи имеют такой же срок. Queued/running не истекают. Запросы проверяют срок перед ответом, фоновая уборка — каждые 15 секунд. Начатая передача может закончиться позже срока. Перезапуск теряет записи в RAM; простой экземпляр может удалиться раньше TTL, если студия перестала обращаться к нему. Повтор истёкшего request создаёт новое задание.

`GET /health` доступен на loopback, возвращает ready/unavailable и не продлевает простой. Генерация ограничена 2700 секундами; при таймауте ComfyUI прерывается с проверкой очереди. Если остановку нельзя подтвердить, backend становится недоступным.

Ответы `POST /interrupt` и удаления `POST /history` проверяются только по статусу 200: ComfyUI возвращает пустое тело. Подтверждённая пустая очередь после таймаута сохраняет backend исправным, следующий start принимается.

Декодирование и обрезка обоих кадров выполняются в потоке под общим семафором на две операции. Перед регистрацией задания повторно проверяются request, свободные места и доступность backend; конкурентные повторы сохраняют один id. 16-битные серые PNG преобразуются из диапазона 0–65535 в 0–255 до RGB, сохраняя полутона.

## Геометрия и граф

| Размер | 16:9 | 9:16 | 1:1 |
| --- | --- | --- | --- |
| 480p | 864×480 | 480×864 | 640×640 |
| 720p | 1280×704 | 704×1280 | 960×960 |

Сетка canvas — 32 пикселя. При 24 fps число кадров округляется вверх до `17k+5`: **5→124, 6→158, 7→175, 8→192, 9→226, 10→243**. Видео не обрезается до ровного числа секунд.

Фиксированные веса: FL2VA pruned INT8 ConvRot, INT8 video VAE, fp32 audio VAE, Qwen3-VL 32B NVFP4-AWQ, Turbo8 LoRA. Семплер `res_multistep`, scheduler `simple`, 8 шагов, denoise=1, 24 fps, MP4/H.264. При `audio=true` сохраняется собственный звук H3; при false аудиодекодер и audio-вход экспорта отсутствуют. История ComfyUI удаляется после каждого задания, `--disable-metadata` остаётся включённым. Кодеки, синхронизация и пики памяти требуют отдельного GPU-испытания.

## Проверка

Из этого каталога: `.venv/Scripts/python.exe -m pytest -q --basetemp=.tmp/pytest-round2 --junitxml=test-results.xml` (Linux: `.venv/bin/python`). Зависимости: `requirements-test.txt`; ComfyUI и torch для тестов не устанавливаются. Сетевой guard разрешает только loopback. Используются синтетические картинки, фиктивные MP4 и credentials; GPU, модели, Vast и платные вызовы не запускались.

`validation.json` связывает пункты brief с файлами и тестами; `test-results.xml` содержит итог pytest. `needs.json` перечисляет работу conductor, включая Opus-review. За пределами этого каталога изменений нет; commit/push не выполнялись.
